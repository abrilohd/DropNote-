# DropNote

DropNote is a focused knowledge vault for saving technical notes before useful ideas disappear. Create notes, organize them by category, search across your collection, and return to the details that matter.

## Deployment On Vercel

DropNote is configured for Vercel's Python runtime. The Vercel function in `api/index.py` loads Django, while `vercel.json` routes incoming requests and collects static files.

Vercel does not provide a persistent local filesystem for application data. Use an external PostgreSQL provider such as Neon or Supabase for production notes.

### 1. Create the Vercel project

1. Open Vercel and choose **Add New Project**.
2. Import the GitHub repository `abrilohd/DropNote-`.
3. Keep the root directory as `./`.
4. Keep the detected Django preset.
5. Click **Deploy**.

The repository already contains the required Vercel configuration, so no framework conversion is needed.

### 2. Create a PostgreSQL database

Create a PostgreSQL database with Neon, Supabase, or another PostgreSQL provider. Copy its connection string, including the username, password, host, port, and database name.

### 3. Add Vercel environment variables

In the Vercel project, open **Settings > Environment Variables** and add these variables for Production:

[Open DropNote](https://your-railway-domain.up.railway.app)

Replace the placeholder URL above with the public domain generated by Railway.
DJANGO_ALLOWED_HOSTS=<your-project>.vercel.app
DJANGO_CSRF_TRUSTED_ORIGINS=https://<your-project>.vercel.app
DATABASE_URL=postgresql://...

DropNote is ready to deploy on Railway as a Django web service. Railway uses the Nixpacks builder, runs migrations before each deployment, and starts the app with Gunicorn using the configuration in `railway.json`.
Use the exact Vercel domain shown under **Settings > Domains**. If you add a custom domain, include both domains as comma-separated values:

```text
DJANGO_ALLOWED_HOSTS=<your-project>.vercel.app,www.example.com
DJANGO_CSRF_TRUSTED_ORIGINS=https://<your-project>.vercel.app,https://www.example.com
```
1. Create a new Railway project from the GitHub repository `abrilohd/DropNote-`.
### 4. Run migrations
3. In the Django service variables, add the PostgreSQL service's `DATABASE_URL` reference and these values:
Run migrations against the production PostgreSQL database from the project root. Do this after creating the database and before testing note creation:
```text
DJANGO_SECRET_KEY=<long-random-secret>
uv sync
uv run python manage.py migrate
```

Use the production `DATABASE_URL` only in your local terminal or a secure release environment. Never commit it to GitHub.

### 5. Redeploy and test

After saving the Vercel variables, open **Deployments** and redeploy the latest `main` commit. Test these routes:

```text
/
/notes/
/notes/new/
/admin/
```

Also test creating, editing, deleting, searching, and filtering notes. Confirm that CSS, JavaScript, and dark mode load correctly.

### Local validation before deployment
5. Generate a Railway public domain in the service's Networking settings.
6. Replace `<railway-domain>` with that exact hostname, redeploy, and verify the live site.

The production database must be PostgreSQL. SQLite remains the local development fallback because Railway's filesystem is not intended for persistent application data.

The Railway service uses these commands automatically:

```

After the Vercel deployment is live, replace the placeholder URL below with the domain from **Settings > Domains**:

[Open DropNote](https://your-project.vercel.app)
uv sync
The `railway.json` file can remain in the repository for a future Railway deployment; it does not affect the Vercel deployment.
uv run python manage.py check --deploy
```
